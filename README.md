# vk-news-collector

Автоматизация группы VK «Тутаев | Главные новости округа».

## Возможности

- ручной сбор новостей в `data/latest.json` через GitHub Actions;
- немедленная публикация только из подтверждённого `publish-request.json`;
- для каждой новостной публикации автоматически создаётся история со ссылкой на пост;
- публикация с изображением из каталога `media/` через поле `image_path`;
- добавление изображения к любой подтверждённой записи;
- статистика публикаций;
- ежедневный сбор комментариев к публикациям за последние семь дней;
- ежедневная подготовка черновика погоды для Тутаева на сегодня и завтра.

Сценарии комментариев и погоды ничего не публикуют и не отвечают пользователям. Их результаты сохраняются как закрытые артефакты GitHub Actions на семь дней.

## Пост с изображением

```json
{
  "confirmed": true,
  "posts": [
    {
      "message": "Текст одобренного поста",
      "image_path": "media/example.png",
      "story_title": "Короткий заголовок для истории",
      "story_text": "Главное в новости. Откройте пост и ответьте в комментариях"
    }
  ]
}
```

Изображение должно находиться внутри `media/`. Отложенная публикация отключена: история создаётся одновременно с постом.

## Выбор площадок

Для каждого одобренного поста поле `targets` определяет площадки:

- `["vk"]` — только VK;
- `["max"]` — только MAX;
- `["vk", "max"]` — обе площадки.

Если поле `targets` отсутствует, используется безопасное значение `["vk"]` — старые очереди не отправляются в MAX автоматически.

```json
{
  "confirmed": true,
  "request_id": "approved-batch-20260826",
  "posts": [
    {
      "targets": ["vk", "max"],
      "publish_date": 1787723700,
      "message": "Текст одобренного поста",
      "source_post": "-38242868_1913688"
    }
  ]
}
```

MAX не поддерживает собственную отложенную публикацию через Bot API, поэтому подтверждённый сценарий GitHub ждёт указанного времени. Один пакет для MAX должен укладываться примерно в 5 часов 45 минут.

## Правило публикации отключений в приложении

С 6 октября 2026 года поручение Лианы опубликовать отключение в приложении также разрешает отправить соответствующее push-уведомление сразу после публикации. Отдельное подтверждение для пуша не требуется.

- Раздел записи: «Отключения».
- Категория пуша (`topic`): `outages`; связанный раздел (`content_type`): `outages`; `content_id`: ID опубликованного отключения.
- Заголовок пуша начинается с «Отключение» и указывает воду, электричество, отопление или другой ресурс.
- Короткий текст содержит затронутую территорию и дату/время. Для будущих работ писать «отключат», для текущих подтверждённых работ «отключено». Не объявлять будущее отключение уже начавшимся.
- Уведомление отправлять жителям, подписанным на категорию отключений, и проверять результат отправки. Создание черновика не считать отправкой.
- Не отправлять повторный пуш при обычной правке текста или повторной обработке той же записи. Уже отправленные уведомления не дублировать.

Это правило работы при публикации через ассистента. Самостоятельная публикация через админку пока требует отдельной отправки через действующий механизм `send-push`; автоматический серверный триггер не настроен.
